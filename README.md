# 매일 적분 (Daily Integral) — 개인용

[dailyintegral.com](https://dailyintegral.com/) 의 "매일 한 문제" 형식을 참고해,
**적분 문제만** 다루도록 직접 만든 개인 학습용 정적 사이트입니다.
문제·해설·채점 엔진·디자인은 모두 이 저장소에서 새로 작성한 것이고,
원본 사이트의 문제나 자산을 가져오지 않습니다.

## 실행

빌드 도구가 필요 없습니다. 파일을 열기만 하면 됩니다.

```bash
# 방법 1: 그냥 열기
xdg-open daily-integral/index.html      # macOS 는 open

# 방법 2: 로컬 서버 (권장 - localStorage 기록이 안정적으로 유지됨)
cd daily-integral && python3 -m http.server 8000
# http://localhost:8000
```

인터넷 연결 없이도 완전히 동작합니다. 수식 렌더링에 쓰는 KaTeX 를
`vendor/katex/` 에 포함해 두었습니다 (MIT, `vendor/katex/LICENSE`).

## 수록 문제 — 898문항 · 4단계

| 단계 | 문항 | 다루는 것 |
|---|---:|---|
| 쉬움 | 174 | 거듭제곱 법칙, 다항식, 기본 삼각·지수·로그, 1차식 치환, 기본 쌍곡선함수 |
| 보통 | 367 | 표준 치환·부분적분, 삼각·쌍곡선 치환표, 완전제곱, 부분분수, 곱-합 공식, 순환 부분적분 |
| 어려움 | 190 | 두세 단계를 엮는 것들 — 유리식 점화식, 고차 삼각(6차), 중근 부분분수, 쌍곡역함수 부분적분, $\int e^{x}(f+f')$ 꼴 |
| **몬스터** | 167 | $x^{4}\pm1$·$x^{6}+1$ 유리식, $\sqrt{\tan x}$, $x^{x}$, 역수 치환 $u=x\pm\frac1x$, 괴상한 분수 지수, 몫의 미분 되짚기, MIT Integration Bee 결승·타이브레이커 |

난이도는 원본 사이트의 easy/medium/hard 감각에 맞췄고, **몬스터**는 그보다 한 단계 위로
따로 만든 등급입니다. 한 단계를 다 돌기 전에는 같은 문제가 다시 나오지 않으므로
쉬움은 174일, 몬스터는 167일 주기로 순환합니다.

**쌍곡선함수**는 전 단계에 걸쳐 들어 있습니다 —
$\sinh,\cosh,\tanh,\operatorname{sech},\operatorname{csch},\coth$ 의 기본 적분부터
$\operatorname{arsinh}/\operatorname{arcosh}/\operatorname{artanh}$ 적분표,
쌍곡선 치환 $x=a\sinh\theta$, $\int\operatorname{sech}^{3}x\,dx$,
$\int e^{ax}\sinh bx\,dx$, $\int\sinh^{4}x\,dx$ 까지.

## 기능

| 기능 | 설명 |
|---|---|
| 오늘의 문제 | 날짜에서 결정되는 문제. 단계별로 하루 한 문제씩 |
| 정적분 | 어려움·몬스터에 정적분 63문항. 답은 `pi^2/6` 같은 상수식으로 쓰고, 값이 맞으면 정답 |
| 연속 학습일 | 오늘의 문제를 풀면 이어지는 스트릭. 하루 건너뛰면 초기화 |
| 힌트 / 해설 | 문제마다 힌트 2개와 단계별 풀이 |
| 연습장 | 정답 확인 옆의 **연습장 열기**. 문제를 위에 띄운 채 모눈종이에 손으로 푼다. 펜·지우개, 색 4가지, 굵기 3단, 되돌리기. 필기는 문제마다 따로 남는다 |
| 펜만 | **S펜·애플펜슬로만** 그려지고 손가락은 무시한다 — 손을 얹고 써도 선이 그어지지 않는다. 터치 기기에서 기본으로 켜지고, 끄면 손가락·마우스로도 그릴 수 있다 |
| 연습 모드 | 단계별 랜덤 출제. 기록과 스트릭에 영향 없음 |
| 연습 하루 몫 | 쉬움 무제한 · 보통 3 · 어려움 7 · 몬스터 1문제. 자정에 초기화 |
| Touch Grass | 몫을 다 쓰고 계속 누르면 잔디밭 그림과 함께 **Touch Grass**. 잔디는 SVG 로 직접 그린다 — 직접 찍었거나 허락받은 사진을 쓰려면 `app.js` 의 `GRASS_PHOTO` 에 경로를 넣으면 된다 |
| 관리자 키 | 연습 하루 몫과 아카이브 지난 날짜를 함께 해제. 키 해시만 소스에 두지만, 브라우저 콘솔로 `localStorage` 를 고치면 뚫린다 — 접근 통제가 아니라 자기 절제용 장치. **안드로이드 앱에서는 묻지 않는다** (직접 깔아서 쓰는 것이므로 처음부터 해제 상태) |
| 아카이브 | 최근 35일 문제를 다시 풀기. 스트릭에 영향 없음. **지난 날짜는 관리자 키로 잠김** (오늘 칸은 항상 열림) |
| 통계 | 해결 수, 최고 스트릭, 첫 시도 성공률, 단계별 소진율 |
| 탐색 | 첫 화면의 구슬 허브에서 단계·모드를 고르고, 되돌아가기 구슬로 복귀 |
| 테마 | 라이트 / 다크 |
| 오프라인 | 서비스 워커가 첫 방문에 전부 받아 둔다. 설치하면 비행기 모드에서도 그대로 돌아간다 |
| 안드로이드 APK | 웹 자산을 통째로 담은 APK 를 Actions 가 빌드한다. `INTERNET` 권한 없이 완전 오프라인 |

기록은 브라우저 `localStorage` 에만 저장되고 외부로 전송되지 않습니다.

## 오프라인 앱으로 쓰기

브라우저 주소창의 설치 버튼(안드로이드 크롬은 "앱 설치", iOS 사파리는 공유 → "홈 화면에 추가")을
누르면 독립 앱으로 깔립니다. 첫 방문 때 서비스 워커가 문제 은행과 KaTeX 폰트까지
전부 받아 두므로, 그 뒤로는 **네트워크 없이도 기능이 하나도 빠지지 않습니다** —
출제·채점·힌트·해설·기록이 모두 브라우저 안에서 돌아가기 때문입니다.

`sw.js` 는 `build-sw.js` 가 만드는 생성물이라 저장소에 두지 않습니다(`.gitignore`).
배포할 때 워크플로가 **실제로 올라가는 파일들의 해시**로 만들어 넣으므로,
파일이 하나라도 바뀌면 캐시 이름이 갈리고 방문자에게 새 버전이 전달됩니다.

로컬에서 오프라인 동작을 확인하려면 먼저 한 번 만들어 주세요.

```sh
node build-sw.js
python3 -m http.server 8000
```

## 안드로이드 APK 설치

브라우저 설치(PWA)와 별개로, **APK 로 깔 수 있는 안드로이드 앱**을 Actions 가 함께 빌드합니다.
웹 자산을 통째로 APK 안에 넣기 때문에 **설치 직후부터, 한 번도 인터넷에 연결하지 않아도** 그대로 돌아갑니다.
매니페스트에 `INTERNET` 권한 자체를 넣지 않았습니다.

### 받는 곳

| 어디서 | 어떻게 |
|---|---|
| 최신 빌드 | Actions → 최근 실행 → 아래 **Artifacts** 의 `apk` 를 내려받아 압축을 풀면 `daily-integral-1.0.<번호>.apk` |
| 릴리스 | `v1.0.0` 처럼 `v` 로 시작하는 태그를 밀면 Releases 페이지에 APK 가 바로 붙습니다 |

```sh
git tag v1.0.0 && git push origin v1.0.0     # 릴리스에 APK 첨부
```

### 설치

내려받은 `.apk` 를 폰으로 옮겨 열면 됩니다. 스토어를 거치지 않으므로
"출처를 알 수 없는 앱" / "이 출처의 앱 설치 허용" 을 한 번 켜 줘야 합니다.
안드로이드 7.0(minSdk 24) 이상이면 설치됩니다.

### 서명

비밀값이 없으면 **디버그 키**로 서명해 그대로 설치 가능한 APK 가 나옵니다.
계속 같은 키로 서명해 덮어쓰기 업데이트를 하고 싶다면 키스토어를 만들어
저장소 **Settings → Secrets and variables → Actions** 에 넣어 주세요.

```sh
keytool -genkeypair -v -keystore release.jks -alias daily-integral \
        -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 release.jks          # 이 문자열을 ANDROID_KEYSTORE_BASE64 에
```

| 비밀값 | 내용 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `release.jks` 를 base64 로 인코딩한 문자열 |
| `ANDROID_KEYSTORE_PASSWORD` | 키스토어 비밀번호 |
| `ANDROID_KEY_ALIAS` | 키 별칭 (`daily-integral`) |
| `ANDROID_KEY_PASSWORD` | 키 비밀번호 |

키스토어 파일과 비밀번호는 저장소에 커밋하지 마세요. 잃어버리면 같은 키로
업데이트를 낼 수 없어 앱을 지웠다 다시 깔아야 합니다.

### 앱 구조

`android/` 는 얇은 웹뷰 껍데기입니다. 출제·채점·힌트·기록이 전부 자바스크립트라
자바 코드는 화면을 띄우는 `MainActivity` 하나뿐입니다.

- 빌드할 때 `syncWebAssets` 가 저장소 루트의 웹 파일을 `app/src/main/assets/` 로 복사합니다 —
  사본을 커밋하지 않으므로 웹을 고치면 앱도 자동으로 따라옵니다.
- `file://` 대신 `WebViewAssetLoader` 로 `https://appassets.androidplatform.net/` 출처를 만들어 띄웁니다.
  `file://` 출처에서는 `localStorage` 가 막히는 기기가 있어, 기록이 날아가지 않게 하려는 것입니다.
- 서비스 워커(`sw.js`)는 APK 에 넣지 않습니다. 자산이 이미 앱 안에 있어 캐시할 이유가 없습니다.
- 뒤로 가기는 한 단계씩 되돌아갑니다 — 연습장이 열려 있으면 연습장만 닫고,
  문제·아카이브·통계 화면이면 첫 화면으로. 첫 화면에서 한 번 더 누르면 종료 안내가 뜨고,
  2초 안에 다시 누르면 앱이 닫힙니다. (한 페이지짜리 사이트라 웹뷰에는 방문 기록이
  하나뿐이어서, 웹 쪽 `window.appBack()` 에 갈 곳이 있는지 물어보는 방식입니다.)
- 기록은 앱 안 `localStorage` 에 쌓이므로 **웹 사이트와 따로 관리**됩니다.
- 앱에서는 관리자 키를 묻지 않습니다. 웹은 주소만 알면 누구나 들어오므로 잠금을 그대로 두지만,
  APK 는 직접 깔아서 쓰는 것이라 연습 하루 몫과 아카이브가 처음부터 열려 있습니다
  (`location.hostname` 이 `appassets.androidplatform.net` 인지로 구분합니다).

## 배포

`main` 에 푸시하면 `.github/workflows/deploy.yml` 이 돌면서

1. `node generate.js` 로 문제 은행을 다시 만들고 커밋된 `problems.js` 와 같은지 확인
2. `node verify.js` 로 전 문항 수치 검증
3. `node grade-test.js` 로 채점 엔진 회귀 테스트
4. `node build-sw.js` 로 서비스 워커 생성
5. 실행에 필요한 파일만 추려 GitHub Pages 로 배포
6. 같은 검증을 통과한 뒤 안드로이드 APK 를 빌드해 Artifacts 로 올림 (태그면 릴리스에도 첨부)

검증이 하나라도 실패하면 배포도 APK 빌드도 하지 않습니다. `generate.js` 같은 개발용 파일은
배포본에서 빠집니다.

> 처음 한 번은 저장소 **Settings → Pages → Source** 를
> `Deploy from a branch` 에서 **`GitHub Actions`** 로 바꿔 줘야 합니다.

## 채점 방식

정답을 문자열로 비교하지 않습니다. 입력한 식을 파싱해 함수로 만든 뒤,
기준 부정적분과 **여러 표본점에서의 차이가 상수인지**를 확인합니다.
덕분에 아래가 모두 정답 처리됩니다.

```
∫ 5/x dx        →  5ln(x) · 5ln|x| · ln(x^5) · 5ln(x) - 7          모두 정답
∫ sin²x dx      →  x/2 - sin(2x)/4 · x/2 - sin(x)cos(x)/2          모두 정답
∫ dx/√(x²+1)    →  asinh(x) · ln(x+sqrt(x^2+1))                    모두 정답
∫ sech x dx     →  atan(sinh(x)) · 2atan(tanh(x/2))                모두 정답
```

적분상수 `+C` 는 써도 되고 안 써도 됩니다. 계수만 틀린 경우
"피적분함수의 몇 배가 되는지" 를 알려 줍니다.

### 입력은 치기 쉽게, 화면은 예쁘게

키보드로 편한 ASCII 를 치면 입력창에서 바로 수식 기호로 바뀝니다.
파서가 두 표기를 모두 읽으므로 어느 쪽으로 쳐도 채점은 같습니다.

| 치는 것 | 보이는 것 |
|---|---|
| `*` | `·` |
| `^2`, `^12`, `^-3` | `²`, `¹²`, `⁻³` |
| `^x`, `^n` | `ˣ`, `ⁿ` |
| `^(2x)`, `^(2x+1)`, `^(-2x)` | `²ˣ`, `²ˣ⁺¹`, `⁻²ˣ` |
| `sqrt(` | `√(` |
| `pi` | `π` |

괄호로 묶인 지수는 닫는 괄호를 치는 순간 통째로 위첨자가 되고 괄호는 사라집니다.
괄호가 범위를 정해 주므로 `e^(2x)` 가 `e²ˣ` 로 바뀌어도 뜻이 흔들리지 않습니다.
지수 안에 위첨자로 옮길 수 없는 것이 있으면 (`x^(1/2)`, `e^(x^2)`) 건드리지 않고,
지수가 아닌 괄호 (`sin(x)`, `2·(x+1)`) 도 그대로 둡니다.

입력창 바로 아래에는 지금 쓴 식이 실제 수식으로 크게 그려집니다 —
`2*sqrt(x^2+1)/3 - pi*x^-2` 를 치면 입력창에는 `2·√(x²+1)/3 − π·x⁻²`,
미리보기에는 분수와 근호가 제대로 조판된 모습이 나옵니다.

입력 문법: `2x` 또는 `2*x`, `x^2` 또는 `x²`, `(x+1)/2`, `sqrt(x)` 또는 `√(x)`,
`ln(x)`, `|x|`, `asin/acos/atan`, `sinh/cosh/tanh/sech/csch/coth`,
`asinh/acosh/atanh`, `sin^2(x)`, `pi` 또는 `π`, `e`, `e^(2x)` 또는 `e²ˣ`.

## 문제 추가·수정하기

`problems.js` 는 **자동 생성 파일**입니다. 직접 고치지 말고 `generate.js` 의
유형(family)을 고친 뒤 다시 생성합니다.

```bash
node generate.js     # problems.js 재생성 (검증 실패 시 파일을 쓰지 않고 중단)
node verify.js       # 생성된 파일을 독립적으로 재검증
node grade-test.js   # 채점 엔진 회귀 테스트
```

유형 하나는 이렇게 생겼습니다. 매개변수를 바꾸면 문항이 한꺼번에 늘어납니다.

```js
[1, 2, 6].forEach(function (a) {
  [1, 3, 4, 9].forEach(function (b) {
    add('medium', '치환적분',
        C(a, 1, 'x/(x^2+' + b + ')'),        // 피적분함수
        C(a, 2, 'ln(x^2+' + b + ')'), {      // 기준 부정적분 (+C 생략)
      domain: [0.1, 2.6],                    // 특이점을 피한 비교 구간
      hints: ['분모의 도함수가 $2x$ 다.', '...'],   // $...$ 안은 수식으로 렌더링
      steps: ['$u=x^{2}+' + b + '$', '...']
    });
  });
});
```

`generate.js` 는 만든 문항마다 기준 부정적분을 수치 미분해 피적분함수와
일치하는지 확인하고, **한 건이라도 어긋나면 `problems.js` 를 쓰지 않고 멈춥니다.**
문제 표시용 LaTeX 와 정답 LaTeX 는 파서의 변환기가 자동으로 만들며,
계수 1·분모 1 같은 군더더기는 생성 시 정리됩니다.

`domain` 은 채점 표본을 뽑는 구간이므로 분모가 0 이 되거나
로그·근호의 정의역을 벗어나는 지점, 그리고 $\tan/\sec$ 의 극점을 피해야 합니다.
